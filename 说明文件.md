二、环境搭建
------------------------------------------------------------

2.1 安装 Python 3.11

下载地址：https://www.python.org/downloads/release/python-3119/
安装时勾选 Add python.exe to PATH
验证：

  py -3.11 --version


2.2 创建虚拟环境

  cd /d E:\Py-project\invoice_sxl
  py -3.11 -m venv venv
  venv\Scripts\activate

激活成功后命令行前会出现 (venv)。


2.3 升级 pip

  python -m pip install --upgrade pip

注意：必须用 python -m pip，不要直接敲 pip。


2.4 安装依赖（严格按顺序）

  python -m pip install PySide6 pymupdf pdfplumber pyinstaller
  python -m pip install "numpy==1.26.4"
  python -m pip install opencv-python-headless==4.10.0.84
  python -m pip install paddlepaddle==2.6.2
  python -m pip install paddleocr==2.7.3

顺序很重要：先降 numpy，再装 opencv 4.x，最后装 Paddle 系。


2.5 验证环境

  python -c "import numpy; print('numpy', numpy.__version__)"
  python -c "import cv2; print('cv2', cv2.__version__)"
  python -c "import paddle; print('paddle', paddle.__version__)"
  python -c "import paddleocr; print('paddleocr', paddleocr.__version__)"
  python -c "import PySide6, fitz, pdfplumber; print('OK')"

期望输出：

  numpy 1.26.4
  cv2 4.14.0
  paddle 2.6.2
  paddleocr 2.7.3
  OK

四、开发环境运行

  python main.py

五、打包：目录形式（onedir）
------------------------------------------------------------

5.1 使用 main.spec（工程已有的配置）

执行：

  pyinstaller --noconfirm --clean main.spec


5.2 产物

  dist\发票整理工具\
  ├── 发票整理工具.exe
  └── _internal\
      ├── paddle\libs\mklml.dll
      ├── paddle\libs\mkldnn.dll
      ├── paddleocr\
      └── ...


5.3 特点

  - 启动快（3~8 秒）
  - 分发需要整个文件夹
  - 体积约 1.0 ~ 1.5 GB
  - 稳定，推荐作为正式发布版本


六、打包：单文件形式（onefile）
------------------------------------------------------------

6.1 使用 main_onefile.spec

执行：

  pyinstaller --noconfirm --clean main_onefile.spec


6.2 产物

  dist\发票整理工具.exe      单个文件


6.3 特点

  - 启动慢（首次 10~20 秒，需解压到临时目录）
  - 分发只发一个 exe
  - 体积约 1.0 ~ 1.5 GB
  - 运行时会生成 %TEMP%\_MEIxxxxxx 临时目录


6.4 main.py 需要加的兼容代码

在文件开头 import 区之后加入：

  # ===================== 单文件 EXE 环境适配 =====================
  if getattr(sys, 'frozen', False):
      _base = Path(sys._MEIPASS)
      for _sub in [r'paddle\libs', r'paddle\base', r'_internal\paddle\libs']:
          _p = _base / _sub
          if _p.is_dir():
              os.environ['PATH'] = str(_p) + os.pathsep + os.environ.get('PATH', '')

  os.environ['KMP_DUPLICATE_LIB_OK'] = 'TRUE'
  # ==============================================================

这段代码同时兼容 onedir 和 onefile 和开发环境，
加入后不会影响目录形式打包。


七、分发部署
------------------------------------------------------------

7.1 onedir 分发

  把 dist\发票整理工具 整个文件夹拷给用户
  用户双击 发票整理工具.exe

  用户双击即可


7.3 目标机器要求

  - Windows 10/11 64 位
  - VC++ 2015-2022 运行库（一般系统自带）
  - 首次运行会联网下载 OCR 模型（约 20~40MB）
  - 之后完全离线可用


八、日常维护
------------------------------------------------------------

8.1 修改代码后重新打包

  venv\Scripts\activate
  pyinstaller --noconfirm --clean main.spec
  或
  pyinstaller --noconfirm --clean main_onefile.spec


8.2 升级某个依赖

  python -m pip install 某包==新版本 -c constraints.txt

升级后必须重新验证：

  python -c "import paddleocr; print('OK')"


8.3 迁移到新电脑

  1) 复制整个 invoice_sxl 文件夹（不含 venv）
  2) 新电脑装 Python 3.11
  3) 重建环境：
     py -3.11 -m venv venv
     venv\Scripts\activate
     python -m pip install -r requirements.txt
  4) 或直接用打包好的 dist 文件夹


8.4 pip 使用原则

  始终用 python -m pip 形式，不要直接敲 pip
  始终带 -c constraints.txt 防止 numpy 被升级

  onefile 启动时间   10 ~ 20 秒

【环境类】

1. pip install 报 WinError 5 拒绝访问
------------------------------------------------------------
现象：
  ERROR: Could not install packages due to an EnvironmentError:
  [WinError 5] 拒绝访问。: '...venv\scripts\pip.exe'

原因：pip.exe 正在被占用，或权限不足。

解决：
  1) 关闭所有使用 venv 的终端窗口
  2) 或直接改用：
     python -m pip install xxx
  3) 或重建 venv：
     deactivate
     rmdir /s /q venv
     py -3.11 -m venv venv
     venv\Scripts\activate
     python -m pip install --upgrade pip


2. 升级 pip 报 To modify pip
------------------------------------------------------------
现象：
  ERROR: To modify pip, please run the following command:
  ...venv\Scripts\python.exe -m pip install --upgrade pip

原因：新版 pip 禁止直接覆盖 pip.exe。

解决：
  python -m pip install --upgrade pip

以后升级 pip 一律用 python -m pip 形式。


3. ModuleNotFoundError: No module named 'pip'
------------------------------------------------------------
原因：pip 升级过程中断，旧版已卸载新版未装上。

解决：
  python -m ensurepip --upgrade
  python -m pip install --upgrade pip

仍不行就重建 venv，参考问题 1。


4. lmdb 源码编译失败 ValueError
------------------------------------------------------------
现象：
  ValueError: path '/home/runner/work/py-lmdb/py-lmdb/build/lib/mdb.c'
  cannot be absolute
  error: subprocess-exited-with-error

原因：py-lmdb 找不到预编译 wheel，尝试源码编译时踩到已知 bug。

解决：下载对应 Python 版本的 whl 本地安装。

  1) 访问 https://pypi.org/project/lmdb/#files
  2) 找文件名类似：
     lmdb-1.4.1-cp311-cp311-win_amd64.whl
     注意 cp311 对应 Python 3.11，win_amd64 对应 64 位
  3) 本地安装：
     python -m pip install lmdb-1.4.1-cp311-cp311-win_amd64.whl


【依赖冲突类】

5. numpy.core.multiarray failed to import
------------------------------------------------------------
现象：
  ImportError: numpy.core.multiarray failed to import
  或 RuntimeError: module compiled against ABI version 0x1000009
     but this version of numpy is 0x2000000

原因：numpy 被升到 2.x，而 Paddle/opencv/imgaug 基于 numpy 1.x 编译。

解决：
  python -m pip install "numpy==1.26.4" --force-reinstall

验证：
  python -c "import numpy; print(numpy.__version__)"
  应输出 1.26.4


6. AttributeError: np.sctypes was removed
------------------------------------------------------------
现象：
  AttributeError: `np.sctypes` was removed in the NumPy 2.0 release

原因：imgaug 库不兼容 numpy 2.x。

解决：同问题 5，把 numpy 锁回 1.26.4。


7. opencv-python-headless 5.x requires numpy>=2
------------------------------------------------------------
现象：
  opencv-python-headless 5.0.0.93 requires numpy>=2,
  but you have numpy 1.26.4 which is incompatible

原因：pip 自动装了 opencv 5.x，与 numpy 1.x 冲突。

解决：
  python -m pip install opencv-python-headless==4.10.0.84


8. RuntimeError: module compiled against ABI version
------------------------------------------------------------
现象：
  RuntimeError: module compiled against ABI version 0x1000009
  but this version of numpy is 0x2000000

原因：同问题 5，numpy 版本与二进制模块不匹配。

解决：同问题 5。


【打包过程类】

9. No module named 'xxx'
------------------------------------------------------------
原因：PyInstaller 未收集该模块。

解决：
  在 main.spec（或 main_onefile.spec）的 hiddenimports 列表里
  添加 'xxx'，重新打包。

  常见漏掉的模块：
    imghdr      标准库，Python 3.13 移除
    lmdb        PaddleOCR 需要
    scipy.io    scipy 子模块
    cv2         opencv
    tools       PaddleOCR 内部
    ppocr       PaddleOCR 内部


10. PackageNotFoundError: No package metadata was found
------------------------------------------------------------
现象：
  importlib.metadata.PackageNotFoundError:
  No package metadata was found for imageio

原因：PyInstaller 收集了代码但没收集 dist-info 元数据。

解决：
  在 spec 的 copy_metadata_list 列表里添加包名，重新打包。

  常见需要复制元数据的包：
    imageio
    imgaug
    paddleocr
    paddlepaddle
    shapely
    pyclipper
    scikit-image
    opencv-python-headless
    numpy
    scipy
    lmdb


11. ValueError: path '...mdb.c' cannot be absolute
------------------------------------------------------------
同问题 4，参考问题 4 解决。


12. imghdr 已弃用（Python 3.13）
------------------------------------------------------------
现象：
  DeprecationWarning: 'imghdr' is deprecated and slated for
  removal in Python 3.13

原因：Python 3.13 已移除 imghdr 标准库。

解决：
  方案一（推荐）：用 Python 3.11 而不是 3.13
  方案二：安装兼容包
    python -m pip install standard-imghdr


【运行时报错类】

13. mklml.dll error code 126
------------------------------------------------------------
现象：
  RuntimeError: (PreconditionNotMet) The third-party dynamic library
  (mklml.dll) that Paddle depends on is not configured correctly.
  (error code is 126)

原因：Paddle 的动态链接库没被打包进去。

解决：
  1) 确认 spec 的 collect_pkgs 列表里有 'paddle'
  2) 重新打包
  3) 检查产物：
     dir /s /b dist\发票整理工具\_internal\paddle\libs\*.dll
     应能看到 mklml.dll、mkldnn.dll、libiomp5md.dll 等

  若仍报错，在 main.py 开头加入：

  # ===================== 单文件 EXE 环境适配 =====================
  if getattr(sys, 'frozen', False):
      _base = Path(sys._MEIPASS)
      for _sub in [r'paddle\libs', r'paddle\base',
                   r'_internal\paddle\libs']:
          _p = _base / _sub
          if _p.is_dir():
              os.environ['PATH'] = (str(_p) + os.pathsep
                                    + os.environ.get('PATH', ''))
  os.environ['KMP_DUPLICATE_LIB_OK'] = 'TRUE'
  # ==============================================================

  然后再重新打包。


14. exe 闪退无任何提示
------------------------------------------------------------
原因：无控制台，看不到错误。

解决：
  1) 打开 main.spec 或 main_onefile.spec
  2) 把 console=False 改成 console=True
  3) 重新打包
  4) 在 CMD 里运行：
     cd dist
     发票整理工具.exe
  5) 完整报错会打印出来


15. exe 启动卡在"正在加载PaddleOCR模型"
------------------------------------------------------------
原因：PaddleOCR 正在联网下载模型（首次运行）。

解决：
  1) 等待 1~3 分钟，模型约 20~40MB
  2) 检查网络是否畅通
  3) 检查 C:\Users\用户名\.paddleocr\ 是否有文件生成
  4) 若长时间不动，关掉 exe 重试


【分发使用类】

16. 换新电脑运行报错
------------------------------------------------------------
可能原因：
  - 目标机器缺 VC++ 运行库
  - 目标机器是 32 位系统
  - onedir 模式只拷了 exe，没拷 _internal 文件夹

解决：
  - 安装 VC++ 2015-2022 运行库
  - 确认系统是 Windows 10/11 64 位
  - onedir 分发必须整个文件夹一起拷


17. 打包体积过大（1GB+）
------------------------------------------------------------
说明：PaddleOCR 系程序正常体积就是 1GB 上下。

可优化项：
  - 确认 spec 里 excludes 已排除：
    matplotlib、tkinter、PyQt5、PyQt6、PySide2
  - 不要用 --onefile，onedir 已经是最优
  - 不要在 venv 里装多余的包


【排查技巧类】

18. 报错处理通用套路
------------------------------------------------------------
按报错类型对号入座：

  No module named 'xxx'
    → 在 hiddenimports 加 'xxx'

  PackageNotFoundError ... xxx
    → 在 copy_metadata_list 加 'xxx'

  xxx.dll not configured / error code 126
    → 在 collect_pkgs 加包含该 DLL 的包
    → 或加 main.py 里的 PATH 修正代码

  FileNotFoundError: 某路径
    → 用 --add-data 或 datas 把文件加进去

  反复循环上面步骤，直到不报错。


19. 如何查看 exe 完整报错
------------------------------------------------------------
 1) spec 里 console=False 改成 True
 2) 重新打包
 3) CMD 里运行 exe，不用双击
 4) 完整堆栈会打印在 CMD 窗口

调试完成后再把 console 改回 False 重新打包，
这样分发给用户的版本没有黑窗。
